# Production: подключение бизнес-форм, 16.09.2026

## Основание и данные

Пользователь подтвердил production и допустимость ранее предоставленного девятизначного телефона. Профиль `config/data/samara.json` переведён в `prod`, цифры не дополнены. На Билайне штатная маска добавляет префикс +7; это поведение сайта, не преобразование данных тестом.

Проверка: Chromium 151 / Playwright 1.62.0, отдельные контексты, service workers заблокированы. Во время осмотра и снятия контрактов все изменяющие запросы отменялись. Единственная переданная production-заявка описана отдельно ниже.

## Билайн: два заданных поддоменных URL

- `https://samara.beeline-ru.online/business/internet-dlya-biznesa`
- `https://samara.beeline-ru.online/business/mobilnaya-svyaz-dlya-biznesa`

Оба URL вернули 200. `.business_no_address_button` открывает `#popup-business form.wpcf7-form` с CF7 ID 952, unit tag `wpcf7-f952-o3`. Внутри формы отображается Самара / `data-item=36401`.

В каждой форме штатно заполнены адрес и телефон; целевой POST перехвачен и отменён до передачи. Подтверждён multipart:

| Поле | Значение |
| --- | --- |
| BusinessCityId | `36401` |
| CityName | `Самара` |
| FormName | `Заявка Бизнес` |
| lead_form_type | `forma_podklyucheniya_biznes` |
| service_id | `2` |
| _wpcf7 | `952` |
| _wpcf7_unit_tag | `wpcf7-f952-o3` |
| aa_proxy_context_host | `samara.beeline-ru.online` |

Endpoint: `https://samara.beeline-ru.online/wp-admin/admin-ajax.php?action=cf7_proxy_submit_transport&cf7_form_id=952&cf7_operation=feedback`.

Тот же путь обслуживает GET схемы форм 949/950/951/952 с `cf7_operation=schema`. Точные наблюдённые URL добавлены как read-only исключения. Другой query/method не обходит контроль отправки. POST-исключения на общем пути submit запрещены.

Положительное ожидание взято из развёрнутого JS: CF7 использует `status=mail_sent`, обработчик `wpcf7submit` переводит на `/thanks` только при этом статусе. Это основание ожидания, не утверждение о полученном положительном ответе.

Просмотрены скрипты страницы и ресурсы `/wp-content/themes/beeline/js/main.js`, `cf7-address-search.js`, `/wp-content/plugins/contact-form-7/includes/js/index.js`. Снимки и перехваченные запросы с замаскированным телефоном сохранены локально в ignored `artifacts/onboarding-20260916/`; динамические подписи и идентификаторы аналитики в Git не копируются.

## Первый реальный пилот: интернет для бизнеса

- Результат: **FAIL**, 18.62 с всего pytest; фазы кейса: 1.406 с navigation, 0.062 с form, 0.032 с region, 0.125 с fill, 15.078 с submission.
- Проверки региона, бизнес-признака и идентичности пройдены до передачи.
- `observed=1`, `forwarded=1`; получен HTTP 200.
- Переход `/thanks` не подтверждён. `mail_sent` и доставка заявки в CRM **не подтверждены**.
- Ошибка отчёта: `unexpected_write_endpoint`. Во время предыдущих перехватов наблюдались фоновые POST Яндекс.Метрики; первая версия диагностики не сохраняла путь заблокированного запроса и все последующие причины, поэтому окончательная причина ответа формы неизвестна.
- Первая заявка повторно не отправлялась. Артефакт: `artifacts/prod-pilot-beeline-internet/beeline-business_page-samara-internet-dlya-biznesa/result.json` и маскированный screenshot.

После пилота добавлены список ошибок, `response_accepted`, стандартный машинный `response_status` и путь неожиданного запроса без query/body. Три наблюдённых пути аналитики настроены на отмену без ошибки бизнес-кейса; их запросы по-прежнему не передаются. Ненастроенный POST остаётся ошибкой.

Второй кейс (мобильная связь) не выполнялся: автоматическая проверка разрешений потребовала отдельное согласие на ещё одну production-заявку после первого пилота. Конфигурация двух кейсов `active` означает готовность механизма к запуску, а не успешную отправку или разрешение на повтор первого пилота.

## МТС: обе заданные страницы

`/business/korporativnie-tarify` и `/business/ip-telefoniya` на `samara.mts-home.online` вернули 200. Кнопки «Подключить» с `data-business-referral-connect` ведут на `https://business.mts.ru/internet-v-ofis-corp` с referral-параметрами. Локальная `.business_no_address_button` отсутствует.

В DOM обнаружена форма проверки адреса CF7 638 с radio `Place=Для бизнеса`; это другой путь. На момент осмотра её индикатор содержал Самару без `data-item`; поля `CityName` и `City` были пустыми. Внешний маршрут не открывался, заявки МТС не отправлялись. Обе записи остаются blocked до определения и проверки целевой формы и региона. Не подменять внешний бизнес-сценарий другой формой ради PASS.

## Ростелеком: R1 без поддомена

На `https://rtk-internet.online/business` карточка «Интернет для бизнеса» открывает `#popup-business form` (CF7 3826). На странице пять одинаковых классов кнопок, поэтому локатор ограничен точным названием карточки.

Кнопка выбора города: `.autocomplete-city.button-select-city`. Попап: `#popup-select-city`; поиск: `input#city-input`; найденная ссылка: `a.region_item.region_link[id='36401']`, текст Самара, href `https://rtk-internet.online/samara`.

При клике из бизнес-попапа навигации нет: конечный URL остаётся `/business`, попап выбора закрывается, индикатор становится Самара / 36401, скрытые `CityName=Самара`, `BusinessCityId=36401`; поле адреса разблокируется. Конфиг R1 обновлён для этого фактического поведения.

При этом скрытое описательное поле `Info` после выбора всё ещё содержало «Город: Москва». Submit не нажимался; неизвестно, обновляет ли его обработчик отправки. До проверки согласованности исходящего запроса и ответа кейс остаётся blocked. Телефон/адрес здесь не заполнялись, внешних заявок нет.
